# AGENTS.md - Developer Guide for mcpmock

Quick reference for AI agents and developers extending this MCP mock server tool.

## Project Overview

**mcpmock** - MCP mock server toolkit for testing, development, and demos.

**Purpose**: Run mock MCP servers from mcpdesc files, record real traffic for replay, and build realistic mock datasets with AI assistance.

**Public Repository**: `https://github.com/cisco-open/mcptoolkit-mock`

**Tech Stack**: TypeScript, Node.js 20+, Commander.js, Ajv, Handlebars, json-schema-faker

**Version Management**: Follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html). All changes must be documented in [CHANGELOG.md](CHANGELOG.md) before release.

**Commands**: 
- `run` - Start mock MCP server from mcpdesc file (Phase 1 ✅)
- `record` - Capture real traffic for replay (Phase 2 ✅)
- `import` - Convert mcptest execution logs to JSONL (Phase 2.6 ✅)
- `completion` - Generate shell completion scripts (v0.2.1 ✅)
- `agents` - AI coding assistant reference (v0.2.1 ✅)
- `build` - AI-assisted mock data builder (Phase 3.1 ✅ v0.4.0)

**Relationship to mcpcontract**: `mcpmock` consumes mcpdesc files generated by `mcpcontract`. They are separate tools in the same ecosystem.

## Code Style Guidelines (Match mcpcontract)

### 1. Imports

**Use Node.js built-in prefix** (`node:*`):

```typescript
// ✅ Correct
import { readFile } from 'node:fs/promises';
import { resolve } from 'node:path';
import { createInterface } from 'node:readline';

// ❌ Incorrect
import { readFile } from 'fs/promises';
```

**Use `.js` extensions** (ES modules):

```typescript
// ✅ Correct
import { McpDescLoader } from './lib/mcpdesc-loader.js';
import type { McpDescFile } from './lib/types.js';

// ❌ Incorrect
import { McpDescLoader } from './lib/mcpdesc-loader';
```

### 2. File Paths

**Use `import.meta.url` for relative paths**:

```typescript
// ✅ Correct
const schemaPath = new URL('../schemas/mcpdesc-schema.json', import.meta.url).pathname;

// ❌ Incorrect
const schemaPath = path.join(__dirname, '../schemas/mcpdesc-schema.json');
```

### 3. Async/Await

**Use async/await consistently** (not callbacks):

```typescript
// ✅ Correct
async function loadDesc(path: string): Promise<McpDescFile> {
  const content = await readFile(path, 'utf-8');
  return JSON.parse(content);
}

// ❌ Incorrect
function loadDesc(path: string, callback: (err, data) => void): void {
  readFile(path, 'utf-8', (err, content) => {
    if (err) return callback(err, null);
    callback(null, JSON.parse(content));
  });
}
```

### 4. Type Annotations

**Explicit return types** for public functions:

```typescript
// ✅ Correct
export async function loadDesc(path: string): Promise<McpDescFile> {
  // ...
}

export function formatJSON(data: unknown, pretty: boolean = true): string {
  // ...
}

// ❌ Incorrect (implicit return type)
export async function loadDesc(path: string) {
  // ...
}
```

### 5. Error Handling

**Throw typed errors, handle with instanceof**:

```typescript
// ✅ Correct
if (!supportedVersions.includes(desc.mcpdesc)) {
  throw new UnsupportedSchemaVersionError(desc.mcpdesc, supportedVersions);
}

// Error handler
if (error instanceof UnsupportedSchemaVersionError) {
  console.error(`Unsupported version: ${error.receivedVersion}`);
}

// ❌ Incorrect
if (!supportedVersions.includes(desc.mcpdesc)) {
  throw new Error('Unsupported version');
}
```

### 6. Logging Pattern

**Use ANSI colors, log to stderr**:

```typescript
// ANSI color codes (same as mcpcontract)
const GREEN = '\x1b[32m';
const YELLOW = '\x1b[33m';
const RED = '\x1b[31m';
const RESET = '\x1b[0m';

// Log to stderr (respects verbose flag)
function log(message: string, options: RunOptions): void {
  if (options.verbose) {
    console.error(`${GREEN}[MCPMOCK]${RESET} ${message}`);
  }
}

// Warning messages (always shown)
function warn(message: string): void {
  console.error(`${YELLOW}[WARN]${RESET} ${message}`);
}

// Error messages (always shown)
function error(message: string): void {
  console.error(`${RED}[ERROR]${RESET} ${message}`);
}
```

**Why stderr?** Keeps stdout clean for protocol data (JSON-RPC over stdio).

## Adding a New Command

### 1. Create Command File

```typescript
// src/commands/newcommand.ts
import { Command } from 'commander';
import { ConfigurationError, type NewOptions } from '../lib/types.js';

// ANSI color codes
const GREEN = '\x1b[32m';
const RESET = '\x1b[0m';

/**
 * Log helper - respects verbose flag
 */
function log(message: string, options: NewOptions): void {
  if (options.verbose) {
    console.error(`${GREEN}[MCPMOCK]${RESET} ${message}`);
  }
}

/**
 * Error handler
 */
function handleError(error: unknown): void {
  if (error instanceof ConfigurationError) {
    console.error('\n❌ Configuration Error:');
    console.error(`   ${error.message}`);
  } else if (error instanceof Error) {
    console.error('\n❌ Unexpected Error:');
    console.error(`   ${error.message}`);
    console.error(`\n   Stack: ${error.stack}`);
  } else {
    console.error('\n❌ Unknown Error:');
    console.error(`   ${String(error)}`);
  }
}

/**
 * Main execution
 */
async function runNewCommand(options: NewOptions): Promise<void> {
  log('Starting new command...', options);
  // Implementation
}

/**
 * Create command
 */
export function newCommand(): Command {
  const cmd = new Command('new');
  
  cmd
    .description('Description of new command')
    .option('--option <value>', 'Option description')
    .option('--verbose', 'Enable detailed logging', false)
    .action(async (options: NewOptions) => {
      try {
        await runNewCommand(options);
      } catch (error) {
        handleError(error);
        process.exit(1);
      }
    });
  
  return cmd;
}
```

## Key Patterns

### Error Handling

**Custom error classes** (same as mcpcontract):

```typescript
export class McpDescLoadError extends Error {
  constructor(message: string, public filePath?: string) {
    super(message);
    this.name = 'McpDescLoadError';
  }
}

export class UnsupportedSchemaVersionError extends Error {
  constructor(
    public receivedVersion: string,
    public supportedVersions: string[]
  ) {
    super(`Unsupported mcpdesc schema version: ${receivedVersion}`);
    this.name = 'UnsupportedSchemaVersionError';
  }
}
```

### File Paths

**Use `new URL()` for ES module paths**:

```typescript
const schemaPath = new URL('../../schemas/mcpdesc-schema.json', import.meta.url).pathname;
```

### Output Formatting

**Reuse pattern from mcpcontract**:

```typescript
import { formatJSON, formatYAML } from './lib/formatters.js';

const output = options.format === 'yaml' 
  ? formatYAML(data) 
  : formatJSON(data, options.pretty);
```

### JSON-RPC Protocol (Mock Server)

**Stdio transport**:

```typescript
import { createInterface } from 'node:readline';

const rl = createInterface({
  input: process.stdin,
  output: process.stdout,
  terminal: false
});

rl.on('line', async (line) => {
  const request = JSON.parse(line);
  const response = await handleRequest(request);
  if (response) {
    console.log(JSON.stringify(response)); // stdout
  }
});
```

**Log to stderr** to preserve stdout for protocol:

```typescript
console.error(`${GREEN}[MCPMOCK]${RESET} ← ${request.method}`); // stderr
console.log(JSON.stringify(response)); // stdout
```

## McpDesc Schema Versioning

**Current version**: v0.7.0 (flat tags)

mcpmock supports mcpdesc schema v0.7.0 with automatic version detection and validation.

**Architecture**:
```typescript
// src/lib/schema-versions.ts - Central version registry
export const SUPPORTED_SCHEMA_VERSIONS = {
  '0.7.0': {
    version: '0.7.0',
    schemaFile: 'mcpdesc-schema-v0.7.0.json',
    supported: true,
    deprecated: false,
    features: ['basic', 'transports', 'security', 'capabilities', 'tags', 'icons', 'annotations', 'flatTags']
  }
};

// src/lib/mcpdesc-loader.ts - Multi-version validator
export class McpDescLoader {
  private validators: Map<string, ValidateFunction> = new Map();
  
  async load(filePath: string): Promise<McpDescFile> {
    const desc = await loadYamlOrJson(filePath);
    const version = desc.mcpdesc;
    
    // Get version-specific validator (lazy compilation + caching)
    const validator = await this.getValidator(version);
    
    // Validate with version-specific schema
    const valid = validator(desc);
    // ...
  }
}

// src/lib/mock-server.ts - Feature detection
export class MockServer {
  private features: ServerFeatures;
  
  private extractFeatures(desc: McpDescFile): ServerFeatures {
    const features: ServerFeatures = {};
    
    // Detect session ID header (0.4.0+)
    if (desc.info?.info?.sessionIdHeader) {
      features.sessionIdHeader = desc.info.info.sessionIdHeader;
    }
    
    // Future: Detect CORS config (0.4.1+)
    // if (desc.info?.corsConfig) { ... }
    
    return features;
  }
}
```

**Version support policy**:
- **Current**: v0.7.0 (only latest version supported)
- **When updating**: Replace the schema entry in `SUPPORTED_SCHEMA_VERSIONS`

**When mcpdesc schema updates**:
1. Copy new schema file from mcpcontract:
   ```bash
   cp ../mcp-contract/schemas/mcpdesc-schema.json schemas/mcpdesc-schema-v0.X.Y.json
   ```
2. Add version to `schema-versions.ts`:
   ```typescript
   '0.X.Y': {
     url: 'https://developer.cisco.com/mcp-description/schema/0.X.Y',
     schemaFile: 'mcpdesc-schema-v0.X.Y.json',
     supported: true,
     deprecated: false,
     features: ['basic', 'newFeature']
   }
   ```
3. Update types if needed (add optional fields for new features)
4. Update mock server feature extraction if needed
5. Add tests for new version
6. Update README.md with supported versions
7. Consider deprecating old versions per support policy

**Design documentation**: See [docs/maintainers/multi-version-schema-support.md](docs/maintainers/multi-version-schema-support.md)

## Release Process

When implementing features or fixes:

1. **Update version** in `package.json` following semantic versioning:
   - MAJOR (X.0.0): Breaking changes to CLI or schema support
   - MINOR (0.X.0): New commands/features (backward-compatible)
   - PATCH (0.0.X): Bug fixes, docs (non-breaking)

2. **Update CHANGELOG.md** with changes under appropriate section:
   - `### Added` - New features
   - `### Changed` - Changes to existing functionality
   - `### Deprecated` - Soon-to-be removed features
   - `### Removed` - Removed features
   - `### Fixed` - Bug fixes
   - `### Security` - Security fixes

3. **Test thoroughly** before committing

4. **Commit and tag**:
   ```bash
   git add .
   git commit -m "Release v0.X.Y"
   git tag v0.X.Y
   git push && git push --tags
   ```
